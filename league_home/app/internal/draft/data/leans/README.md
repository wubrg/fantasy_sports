# Lean sets

A lean set is one source of opinion about players. Each set is a CSV named
for its stem: `mine.csv` is the set `mine`.

```
player,lean,cap,note
Ashton Jeanty,must,,"the risk ceiling sets the bid, not a guess"
```

`lean` is `must`, `up`, `down`, or `dnd`. `cap` is optional and only ever
tightens a must-have. Lines beginning `#` are comments.

## Why more than one file

The opinions have different standing. Yours are convictions you will act on;
an analyst's are evidence you asked for. In one file you would have to edit
someone else's reads to hold your own, and a regeneration would silently
overwrite you.

Precedence is the order you list them. `-leans mine,menton` means your reads
win and Menton fills in everyone you have no opinion about. The losing read
is not thrown away — it is recorded, and the board marks players the sets
disagree about.

## Hand-written vs generated

`mine.csv` is yours. Nothing regenerates it.

Generated sets carry a `# generated by draftroom leans -generate` header, and
that marker is the only thing that makes a file eligible to be overwritten —
a set without it is treated as hand-written and left alone.

Generated sets are **not committed**. They are derived from the private
source repo, and this repo is public. `.gitignore` here allows `mine.csv` and
excludes the rest, so a regeneration cannot accidentally publish an analyst's
work. Rebuild them locally:

```sh
make leans-generate      # rebuild every generated set
make leans               # show the merged picture and any disagreements
```

## Sets

| Set | Source | What a lean means |
|---|---|---|
| `mine` | you | what you will and will not do |
| `menton` | `fantasypoints-big3-2026.csv` | two of the Big-3 traits leans up, none leans down |

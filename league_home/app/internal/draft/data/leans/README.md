# Lean sets

A lean set is one source of opinion about players. Each set is a YAML file
named for its stem: `mine.yaml` is the set `mine`.

```yaml
must:
  - Ashton Jeanty
up:
  - Chase Brown
  - A.J. Brown
down:
  - Kyle Pitts
dnd:
  - Cam Akers

# looked at him, no opinion — silences a lower-precedence set
none:
  - Jaylen Waddle

# written down, not ruled on yet
undecided:
  - Colston Loveland

# both optional, and rare
caps:
  Ashton Jeanty: 48
notes:
  Ashton Jeanty: the risk ceiling sets the bid, not a guess
```

Players are grouped under the read rather than carrying it as a field,
because that is the shape the file is actually edited in — often on a phone,
a line at a time. Deciding you like someone is one line under a heading you
already believe. `caps` and `notes` sit apart because both are rare, and
threading them through every entry would cost a line to say nothing on most
of them.

`caps` only ever tightens a must-have. Lines beginning `#` are comments.

### What the headings mean

`must` and `up` are not degrees of the same thing. `up`/`down` are
conviction — a claim that a player's range is better or worse than the
median. `must` is acquisition: you are not leaving the draft without him,
and you accept paying above your own estimate to do it. `dnd` is a refusal,
not a discount.

`none` and `undecided` are not the same. `none` is a read — you looked and
hold no opinion — and it outranks a lower-precedence set that does hold one,
which is how the board clears a lean it inherited from an analyst.
`undecided` records a name without a read. It is a real state — you wrote
him down before ruling on him — and `draftroom leans` prints those names so
one you have not decided cannot pass for one you have.

### Things that are errors, on purpose

- A heading that is not one of the above. A misspelled `ups:` would
  otherwise silently drop every name under it.
- A `caps` or `notes` entry naming a player who appears in no heading. That
  is a typo every time, and it would otherwise apply to nobody.
- The same player under two headings. One file holds one read per player;
  disagreement is what a second set is for.
- A cap under $1.

## Checking a set

```sh
make leans LEANS=mine,wubrg-lean     # merged picture, disagreements, and typos
```

Besides the merge, this reports the undecided names and any read that names
a player the projection source does not have — with the nearest real player
as a suggestion. A lean is applied by name, so a name typed wrong is not an
error, it is simply absent from the board. That is worth catching before the
draft rather than during it.

## The CSV format

The older row-per-player CSV (`player,lean,cap,note`) is still read, so an
existing set keeps working. A set present in both formats resolves to the
YAML one. To convert:

```sh
draftroom leans -convert -leans mine,wubrg-lean
```

This writes the YAML beside the original and changes nothing else. If a set
is a symlink into a notes vault, the YAML is written beside the **target**,
not the link — a real file next to the link would sit in front of it, and
every later edit in the vault would stop reaching the board without saying
so. The command prints the `ln -sfn` to re-point it when you are ready.

## Why more than one file

The opinions have different standing. Yours are convictions you will act on;
an analyst's are evidence you asked for. In one file you would have to edit
someone else's reads to hold your own, and a regeneration would silently
overwrite you.

Precedence is the order you list them. `-leans mine,menton` means your reads
win and Menton fills in everyone you have no opinion about. The losing read
is not thrown away — it is recorded, and the board marks players the sets
disagree about.

## Hand-written vs generated

`mine.yaml` is yours. Nothing regenerates it.

Generated sets carry a `# generated by draftroom leans -generate` header, and
that marker is the only thing that makes a file eligible to be overwritten —
a set without it is treated as hand-written and left alone, in either format.

Generated sets are **not committed**. They are derived from the private
source repo, and this repo is public. `.gitignore` here allows `mine.yaml`
and excludes the rest, so a regeneration cannot accidentally publish an
analyst's work. Rebuild them locally:

```sh
make leans-generate      # rebuild every generated set
make leans               # show the merged picture and any disagreements
```
